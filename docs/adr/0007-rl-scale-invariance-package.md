# RL scale-invariance package: order-up-to action decoder, demand-units inventory feature, log-uniform domain randomisation

ADR 0005 identified that the RL action decoder breaks scale-transfer by expressing order quantity in capacity-units (`qty = order_frac × free_space / K`) rather than demand-units, and proposed `qty = clamp(order_frac × demand_horizon × recent_sales_rate, 0, per_sku_free_space)` as the fix. The diagnosis was correct, but the proposed fix has three implementation problems that surface under inspection. (1) The multiplicative-scalar parameterisation `order_frac × H × rate` puts the steady-state target action off-centre from PPO's symmetric-Gaussian init: at default `H = 10`, `delivery_lag = 3`, the natural-policy action is `order_frac ≈ 0.3` (`order_raw ≈ −0.4`), so the agent must drift downward in early updates before it starts behaving sensibly. (2) The proposed `cold_start_qty: int = 0` default creates a structural deadlock when paired with the env's `init_stock_pct = 0.0` (`src/rl/episode_sampler.py:272`): zero inventory at episode start → zero realised sales → zero rate → zero qty for *any* action → zero sales forever, no gradient signal, no learning. (3) The framing addresses only the action side of scale-invariance while leaving the encoder's `inventory / per_sku_capacity`, `recent_sales / per_sku_capacity`, and `pending / per_sku_capacity` features clipped to `[0, 1]` — saturating at training scale (capacity 200, per-SKU slice 40) and underutilising the dynamic range at flagship scale (capacity 10_000, per-SKU slice 2_000, features bunched in `[0, 0.05]`). The policy net's response surface in the low-feature regime was never explored during training, so the decoder fix is necessary but not sufficient. ADR 0005 is also out of date in two ways since shipping: ADR 0006 replaced `BaselinePolicy` with `OrderUpToPolicy` as the CRN comparison anchor (the 0005 regression-test description still names the old class), and the TextbookReorderPolicy family ADR 0006 introduces uses censored-sales rate estimation and two-pass fair-share allocation — primitives we want the RL decoder to mirror so the two policies are speaking the same language at the clamp and rate-estimator level.

**Decision — Six-part scale-invariance package supersedes ADR 0005's decoder-only fix.**

(a) **Order-up-to action parameterisation.** `decode_action` emits `qty[pid] = max(0, target_lt × effective_rate[pid] − (inventory[pid] + pending[pid]))`, where `target_lt = clip(target_centre_lead_times + order_raw × target_half_span_lead_times, 0, target_max_lead_times)`. `RLConfig` gains `target_centre_lead_times: int = 15`, `target_half_span_lead_times: int = 15`, `target_max_lead_times: int = 30`. At defaults, `order_raw = 0` reproduces `PeriodicOrderUpToPolicy(R=1, S=15·rate)` exactly (price half also centres at `1.0 × MSRP`, matching the textbook policy's flat-pricing rule). The natural-init policy is therefore a textbook periodic order-up-to baseline, and PPO learns deviations from it rather than searching for a sensible operating point from scratch.

(b) **Cold-start via market-derived demand prior.** The env reads the realised `base_demand` scalar from `market.params.base_demand` at `reset()` and passes it to both encoder and decoder. `effective_rate[pid] = max(rolling_5_mean_sales[pid], base_demand_prior)`. No separate cold-start branch; the prior simply floors the rate until enough realised-sales history accumulates. This is scale-invariant by construction (`base_demand` is in demand-units) and hands off smoothly to the realised rate once the rolling window is populated (typically by tick 5–10).

(c) **Inventory position and fair-share clamp.** Position = on-hand + pending (the textbook inventory-position definition). Per-SKU shelf headroom = `capacity − inventory[pid] − pending[pid]` (no equal-split rule). After per-SKU requested qty is computed, a two-pass allocator runs: pass 1 caps each request at the per-SKU physical headroom; pass 2 proportionally scales all requests if their sum exceeds `capacity − total_inventory − total_pending`. Mirrors `TextbookReorderPolicy._allocate_*` (ADR 0006) so the RL decoder and the comparison-anchor baseline allocate identically at the clamp boundary — which is where they differ most on the first tick of each episode.

(d) **Encoder gains a demand-units inventory feature.** `N_PER_SKU` grows from 13 to 14. New slot 13 carries `clip(inventory[pid] / effective_rate[pid], 0, max_inventory_lt) / max_inventory_lt`, interpretable as "lead-times of cover on hand, normalised to `[0, 1]` with a 30-lead-time ceiling". `RLConfig` gains `max_inventory_lt: float = 30.0`. The existing capacity-units inventory feature (slot 0) is retained — it carries shelf-saturation signal that's useful for *pricing* decisions even though it's the wrong frame for *ordering*. Both signals coexist; the policy learns which to attend to when.

(e) **Log-uniform domain randomisation over scales.** `RLConfig.capacity_dist` defaults to `LogUniform(100, 10_000)` (was `Uniform(150, 400)`); `RLConfig.balance_dist` defaults to `LogUniform(10_000, 1_000_000)` (was `Uniform(15_000, 40_000)`). Two orders of magnitude of variation, sampled fresh each `reset()`. `LogUniform(lo, hi)` is a new `Distribution` subclass in `src/sim/distributions.py`. The widening puts both the small-store regime and the flagship-deployment regime in-distribution for a *single* training run, and acts as a continuous scale-invariance test during training: if the other changes work, training reward should be roughly uniform across the log-capacity range; if not, the uneven reward signal surfaces the gap before the held-out evaluation does.

(f) **Validation gates, three-tier, blocking.** *Tier 1 (unit tests):* `decode_action` cold-start branch returns positive qty at `rate=0` via the prior; returns zero qty at `position = target_lt × effective_rate`; two-pass clamp never returns a total qty exceeding free space. `encode_observation` new slot-13 feature is finite, in `[0, 1]`, and matches the spec formula. *Tier 2 (env, no training):* env rollout with a deterministic `action = 0` policy matches `PeriodicOrderUpToPolicy(R=1, S=15·rate)` on the same `(world_seed, init_seed)` from tick 1 onward — tick-0 cold-starts diverge by construction (RL uses prior, baseline uses cash-budget pilot) and are covered by Tier 1. *Tier 3 (post-retraining):* paired-CRN eval against `OrderUpToPolicy` on two held-out 32-seed sets (`small`: `capacity = Uniform(150, 400)`; `flagship`: `capacity = Constant(10_000)`); all three must pass: (i) mean paired uplift > 0 at both scales, 95% CI excluding zero; (ii) flagship uplift within 2× of small-scale uplift (log-ratio in `[−ln 2, +ln 2]`); (iii) average tick-0 cold-start qty per SKU across the 64 seeds is in `[0.5, 2.0] × base_demand_prior × target_centre_lead_times`.

Considered alternatives:

(a) **Land ADR 0005 verbatim and address the encoder later.** Cleaner per-ADR scope, but pays the retraining cost twice and ships a known partial fix. The encoder change is mechanically small (one new feature slot); the retraining is the expensive step. Bundling them costs one retraining cycle for two improvements.

(b) **Multiplicative-scalar parameterisation (ADR 0005's `qty = order_frac × H × rate`).** Off-centre natural-policy action; agent spends early PPO updates learning the downward bias before it can address substantive ordering choices. Order-up-to centring is strictly cheaper at no expressive cost — every order qty reachable under (a) of this ADR is reachable under the multiplicative form and vice versa.

(c) **Bipolar-around-naive-replenishment (`qty = (delivery_lag × rate) × (1 + α × order_raw)`).** Also centres at zero, but couples the decoder to a heuristic constant (`delivery_lag × rate`) that isn't the same target as the comparison baseline's S. Order-up-to gets the centring property *and* matches the baseline at action=0 — strictly stronger.

(d) **Flat `cold_start_qty: int` (ADR 0005's mechanism).** Re-introduces the scale dependence the ADR is fighting: a constant qty is wrong by `base_demand_high / base_demand_low` across the distribution. The market-derived prior is in demand-units by construction.

(e) **Per-SKU equal-split shelf clamp (status quo decoder).** Cold-start tick: 5 SKUs each request `15 × prior ≈ 75` units against `capacity / K = 40` per-SKU budget; every cold-start order is clipped regardless of total free space available. Fair-share uses the global pool while respecting per-SKU physical limits.

(f) **Replace capacity-units inventory feature with demand-units outright (option Z in the design tree).** Shelf-saturation signal is still useful for pricing decisions. Keep both — the marginal cost is one feature slot.

(g) **No domain randomisation.** Defensible if scale-invariance is complete, but unverifiable in advance. Log-uniform DR is cheap insurance and a continuous test signal; if invariance is real, the agent doesn't lose anything by seeing varied scales.

(h) **Recurrent policy with action history (ADR 0005 alternative (c)).** Deferred. Architecturally heavier, addresses a different failure mode (the policy can't track its own past actions). Worth revisiting only if (a)–(g) leave a measurable gap in Tier 3.

**Migration.** The `runs/fashion_run` checkpoint and any other ADR-0005-era checkpoints will not transfer — the obs shape changes (`N_PER_SKU` 13 → 14), and the action-to-qty mapping is different. Retraining is required. `RLConfig`'s ADR-0005 fields (`demand_horizon`, `cold_start_qty`) are removed before they ship to code; the replacement fields are listed in (a)–(e) above. New code surface: `LogUniform(lo, hi)` in `src/sim/distributions.py`; new fields on `RLConfig` (see (a), (b), (d), (e)); `RLEnv.reset()` stashes `base_demand_prior` and computes per-tick `effective_rate` once, passed to both encoder and decoder; rewrite of `decode_action` and slot-13 addition in `encode_observation`. Tier 1 tests extend `tests/rl/test_encoders.py`; Tier 2 is a new `tests/rl/test_centring_sanity.py`; Tier 3 is a paired-CRN evaluation script that extends `src/rl/eval.py` with a small + flagship eval-set runner. The `Actor` / `Critic` architectures in `src/rl/agents/ppo.py` need no edit beyond consuming the new `observation_dim(K_active)` value — the input layer rebuilds automatically from the env's observation space.

This ADR supersedes ADR 0005. ADR 0005 remains in `docs/adr/` as the historical record of the original decoder-only diagnosis and the empirical observation (flagship checkpoint losing ~$200k) that motivated the work.
