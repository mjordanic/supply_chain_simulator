# Textbook reorder-policy family replaces the heuristic baseline as the RL comparison anchor

The previous `BaselinePolicy` in `src/sim/policy.py` is a 660-line heuristic that exposes 20+ entangled hyperparameters (`min_qty`, `init_qty_factor`, `review_interval`, `target_active_count`, `promo_threshold`, `promo_discount`, `slow_sales_limit`, `stock_lo_ratio`, `price_up_factor`, `trend_threshold`, `inactive_price_factor`, `reorder_factor`, `qty_factor`, etc.) governing reorder qty, dynamic pricing, promotions, catalog rotation, and cooldowns. As an RL comparison anchor this is doubly problematic: (a) its behaviour is sensitive to every kwarg and varies wildly across worlds, so "RL beats baseline" depends on which kwargs the baseline was given; (b) on the LLM fashion world at flagship scale (`capacity=10_000`, `balance=$1M`) the kwargs shipped in `notebooks/07-rl_vs_baseline_per_product.ipynb` lose money outright over a 180-tick episode — a CRN test where *both* sides lose is uninformative about whether RL learned anything useful. The reward function is correct and the simulation mechanics are correct; the comparison anchor is what fails.

**Decision — Replace `BaselinePolicy` with a family of four textbook reorder policies sharing one abstract base, and name (s,S) order-up-to as the canonical RL comparison anchor.** Six classes in `src/sim/policy.py`: `TextbookReorderPolicy` (public abstract base) provides the shared machinery — censored-sales rate estimator over `delivery_lag`-many recent ticks, two-pass fair-share allocator across capacity and cash, cash-budget cold-start "pilot order" (`opening_budget_pct=0.50`), opt-in adaptive safety stock (`stockout_safety_bonus_ticks=0` by default). `OrderUpToPolicy` (s,S, continuous review, the new RL comparison anchor), `ReorderPointPolicy` (s,Q), `PeriodicOrderUpToPolicy` (R,S), and `PeriodicReorderPolicy` (R,s,S) each implement two ~10-line abstract hooks: `_trigger(pid, step, position, rate) -> bool` and `_quantity(pid, position, rate) -> int`. All four emit `activate=[]` / `deactivate=[]` / `promotions={}` and a flat `price[pid] = base_price[pid]` (no cost floor) — the policies are pure inventory rules with exogenous pricing, exactly as in Silver/Pyke/Peterson and the standard inventory-theory references. Levels `s` and `S` are expressed in lead-times-of-demand (`s = (delivery_lag + safety_lead_ticks) × rate`, `S = (delivery_lag + safety_lead_ticks + cover_horizon_ticks) × rate`) so the policies are scale-invariant in capacity by construction — the same defaults work for a $20k corner shop and a $1M flagship. The previous `BaselinePolicy` is renamed `HeuristicPolicy` and retained only in `scenarios/example_*.py` for parameter-demo purposes; no class named `BaselinePolicy` survives the change, so every existing import is a hard `ImportError` that forces the call site to choose intent (kitchen-sink demo vs (s,S) comparison anchor) consciously.

Considered alternatives:

(a) **Tune the existing `BaselinePolicy` harder.** Search over the 20+ hyperparameters per world archetype to find a baseline that consistently beats a no-op strategy. Rejected because tuning-per-world is the exact failure mode we want to eliminate from the comparison: the RL claim should be "RL beats a *defensible textbook competitor* across worlds," not "RL beats a baseline that has been hand-tuned to be just-good-enough on this world." Tuning effort also doesn't transfer when a new archetype is added.

(b) **Ship only (s,S) and skip the other three variants.** A single textbook policy is enough to fix the immediate comparison problem in `nb06` / `nb07`. Rejected because the marginal cost is ~30–50 LOC per sibling once the base class exists, and a *ladder* of textbook competitors gives stronger evidence than a single point: an RL agent that beats (s,S) but loses to (R,s,S) on one world has learned something specific about continuous review rather than general inventory policy; an agent that beats all four can claim genuine optimisation. The lineup also makes follow-up ablation work cheaper (e.g. "is the periodic-review constraint what RL exploits?").

(c) **Hybrid policy: textbook ordering with the existing heuristic pricing and promotion machinery.** Keep the dynamic-pricing factor, cross-product price adjustments, and promo planner from the current `BaselinePolicy`; replace only the order-qty rule. Rejected because pricing complexity was a major contributor to the confounded `nb07` comparison: when RL beats the heuristic it is unclear whether the win comes from better ordering or better pricing or both. A textbook policy with flat `base_price[pid]` isolates the inventory decision, lets us measure the inventory-only contribution cleanly, and leaves room for a future *pricing-only* RL comparison against the same flat baseline.

(d) **Domain-randomise the heuristic baseline's kwargs across episodes.** Sample `min_qty`, `qty_factor`, `promo_discount` etc. from distributions per CRN seed, average over the ensemble. Rejected because it inflates evaluation cost (~K× more rollouts to estimate the same paired uplift) without resolving the underlying issue: the heuristic family doesn't span the space of reasonable supply-chain policies, so the randomisation samples from a biased distribution. A textbook policy is a well-defined point in policy-space; an ensemble of bad heuristics is not.

**Migration.** No class named `BaselinePolicy` exists in the post-change codebase. 20 files migrate: 4 example scenarios and 2 tests adopt `HeuristicPolicy` (a pure rename — same class body, same behaviour, same kwargs); 3 production scenarios (`llm_world_20.py`, `llm_world_100.py`, `llm_world_1000.py`), 5 tests, 2 notebooks (`06-compare_rl_vs_baseline.ipynb`, `07-rl_vs_baseline_per_product.ipynb`), and the RL training/eval modules (`src/rl/train.py`, `src/rl/eval.py`) adopt `OrderUpToPolicy` with default kwargs — the old kwargs refer to behaviour the textbook policy does not have, so they are *dropped* rather than translated. `tests/sim/test_regression_snapshot.py` regenerates its pinned-trajectory snapshot on `OrderUpToPolicy` for the new regression target; the old `HeuristicPolicy` trajectory is no longer pinned (a deliberate trade — the heuristic exists for demonstration, not as a regression anchor). `src/rl/eval.py`'s `evaluate(rl_policy_fn, baseline_policy_factory, …)` interface is unchanged; only the type-hint import and the factory body in `src/rl/train.py` switch. `CONTEXT.md` updates the `Policy` and `CRN-paired eval` glossary entries and adds a new entry for the `TextbookReorderPolicy` family.

**Connection to ADR 0005.** Both ADRs centre demand-units as the canonical scale. ADR 0005 makes the RL action decoder demand-relative (`qty = order_frac × demand_horizon × recent_sales_rate`); this ADR makes the baseline's reorder point and order-up-to level demand-relative (`s = (lead + safety) × rate`, `S = (lead + safety + cover) × rate`). The two changes are independent but compounding: after both land, RL and the textbook baseline live in the same demand-unit system, so paired CRN comparisons are apples-to-apples across capacity scales without requiring scale-specific tuning of either side. Either ADR can ship before the other; the comparison-fairness improvement is unlocked only when both are in.
