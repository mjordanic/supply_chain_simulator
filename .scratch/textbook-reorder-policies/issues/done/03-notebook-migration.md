## What to build

After issue 02 lands, `BaselinePolicy` no longer exists in the source tree. The two analysis notebooks that compare RL against the baseline still reference `BaselinePolicy` by name in imports, in markdown narrative, and in their `build_baseline_policy()` helper bodies. This slice migrates both notebooks so they execute end-to-end against `OrderUpToPolicy`.

The notebook surface:

**`notebooks/06-compare_rl_vs_baseline.ipynb`**
- Imports: replace `from src.sim.policy import BaselinePolicy` with `from src.sim.policy import OrderUpToPolicy`.
- `build_baseline_policy()` helper: body becomes `return OrderUpToPolicy()` (defaults only — old heuristic kwargs are dropped, per the PRD's "kwargs refer to behaviour the textbook policy does not have" rule).
- Markdown narrative: every prose reference to "the baseline" or "`BaselinePolicy`" is updated to name `OrderUpToPolicy` (the (s,S) textbook reorder policy) explicitly. PRD user story 19: "I want the prose to refer to `OrderUpToPolicy` explicitly (not the generic 'baseline'), so that the comparison protocol is self-explanatory."
- The headline comparison cells (paired-uplift plot, per-seed delta) should now show a curve where the new baseline is *not* losing money in-distribution — confirms PRD user story 2 ("compare RL against a policy that does not itself lose money").

**`notebooks/07-rl_vs_baseline_per_product.ipynb`**
- Same surface as notebook 06: imports, `build_baseline_policy()` body, markdown narrative.
- Per-product equity / cumulative-P&L curves should now reflect an apples-to-apples competitor at the training distribution scale (`Uniform(150, 400)` capacity, `Uniform(15_000, 40_000)` balance) — PRD user story 3.

Notebook outputs (the cell execution counts, the embedded figures) should be regenerated by running the notebook fresh, not hand-edited. The verification step is `uv run jupyter nbconvert --to notebook --execute --inplace notebooks/06-*.ipynb` (and the same for `notebooks/07-*.ipynb`) — both must complete without raising.

This slice does not touch the `tests/` or `src/` trees. If a regression in source code is uncovered while executing the notebooks, file a follow-up issue; do not bundle the fix into this slice.
